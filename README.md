## 聚梦画布（Jumeng Canvas）说明

本仓库画布项目已实现 **HMAC 会话认证**（非 JWT 为主）与 **项目级协同授权**。实施安全规范时须 **同时对照** 生成任务架构方案（Submit/Poll/MQ/Redis 改造），安全要求不得与现有部署及该方案冲突。

| 文档 | 用途 |
|------|------|
| [聚梦画布-生成任务性能改造方案](../ai_read/聚梦画布-生成任务性能改造方案.md) | **架构权威**：API 异步入库、MQ submit、Redis 闹钟/Poll、算力预扣时机、4 lane 灰度 |
| [聚梦画布生产部署架构](../ai_read/聚梦画布生产部署架构.md) | ECS/systemd/env 现状 |
| [14.Linux安全](./14.Linux安全.md) | SSH/安全组/MQ 网络（**不强制改部署**） |
| [17.项目协同安全规范](./17.项目协同安全规范.md) | 项目级 RBAC、协作算力 |

画布专项约定：

- **02 认证授权**：JWT 条目为通用参考；画布 **保留** HMAC 会话，仅加强 **项目 membership** 校验
- **17 项目协同**：新增/修改带 `projectId` 的功能 **必读**
- **生成任务改造**：安全规范中的幂等、算力、Redis、MQ、限流条目以性能方案 **第十节通用约定** 与 **第十一节生产约束** 为准；**现状** 仍为 4 lane monolithic Worker + 无 MQ，改造按 lane 灰度，不要求一步到位
- 业务文档：`canvas/doc/features/project-collaboration.md`

## 适用对象

- 后端开发工程师（Python）
- 前端开发工程师（React）
- DevOps / SRE
- 安全工程师
- 技术管理者

## 使用方式

1. **新项目**：从 01 开始依次落地，在架构阶段引入安全设计
2. **存量项目**：重点使用 15_上线Checklist.md 逐项排查，按优先级修复
3. **CI/CD 集成**：参考 16_自动化扫描.md 配置流水线安全门禁
